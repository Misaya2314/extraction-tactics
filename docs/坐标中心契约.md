# 三维地格坐标中心契约

本项目的逻辑格使用 `Vector3i(x, level, z)`。`TacticalMapAuthor.grid_origin` 和 `TacticalMapDefinition.origin` 表示 GridMap 的局部原点，也就是逻辑格 `(0, 0, 0)` 的角点，不是格子中心。

固定单元尺寸为 `Vector3(2, 2, 2)` 时，格子中心为：

`origin + (Vector3(cell) + Vector3(0.5, 0.5, 0.5)) * cell_dimensions`

这与 Godot 4 的 `GridMap.map_to_local(cell)` 一致。地板 MeshLibrary 的 `mesh_transform` 只负责网格内容相对单元中心的高度偏移；单位根节点、出生标记、地图物件标记、移动路径目标和移动高亮都必须使用同一个中心坐标。

上层平台的 `level` 同样参与半格偏移：`level = 0` 的中心 Y 为 `1`，`level = 1` 的中心 Y 为 `3`。因此不能再用 `origin + Vector3(cell) * cell_dimensions` 作为单位站立点。

反向转换使用与 `GridMap.local_to_map()` 一致的包含格规则：对每个轴计算 `floor((world - origin) / cell_dimensions)`。地图作者脚本会优先调用 `FloorGrid.map_to_local()`，运行时 `GridModel` 使用相同公式。

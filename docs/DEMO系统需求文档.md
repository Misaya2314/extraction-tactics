# DEMO 系统需求文档

| **文档版本** | V0.1 |
| --- | --- |
| **文档用途** | 简易可玩 DEMO 开发需求 |
| **核心目标** | 验证“探索—接敌—战棋—搜刮—撤离”基础闭环 |
| **开发范围** | 单地图 / 小队制 / 回合制 / 基础搜打撤 |
| **日期** | 2026-08-11 |

文档原则：仅定义基础可玩闭环所需系统，不包含正式版本的完整内容生产与长线玩法。

# 1. 文档目的

本文件用于明确“战棋 × 搜打撤”简易 DEMO 的基础系统范围、最低功能要求与验收标准，作为程序、美术和策划拆分开发任务的统一依据。

DEMO 不追求完整内容量与长期可玩性，优先验证核心玩法是否可以形成完整、可理解、可操作的体验闭环。

# 2. DEMO体验目标

- 玩家能够在格子化地图中控制多个单位进行移动、攻击与交互。
- 玩家能够通过有限视野探索地图，并在发现敌人后进入回合制战斗。
- 玩家能够击败或绕开敌人，搜索战利品并进行基础背包管理。
- 玩家能够自主选择继续深入或前往撤离点结束本局。
- 成功撤离后能够完成战利品结算；全队失败时本局战利品丢失。

# 3. DEMO基础流程

| **1** | **2** | **3** | **4** | **5** | **6** | **7** | **8** |

# 5. P0 基础系统需求

## 5.1 Grid 地图格系统 \[P0\]

**系统目标：**建立战棋地图的统一空间表达，为移动、寻路、占用、视野和交互提供基础数据。

**核心需求：**

- 采用方形格作为 DEMO 默认地图单元。
- 每个格子记录格子坐标、世界坐标、是否可通行、占用状态和基础高度信息。
- 支持世界坐标与格子坐标双向转换。
- 支持查询相邻格、合法移动格和格子占用对象。
- 支持可移动格、目标格等基础可视化高亮。

**DEMO验收标准：**玩家可在灰盒场景中看到有效格子范围；系统能够正确判断可走与不可走区域。

## 5.2 地图阻挡与寻路系统 \[P0\]

**系统目标：**保证单位能够按照规则在格子地图中计算并执行有效移动路径。

**核心需求：**

- 墙体、关闭的门、占用格等对象可阻止通行。
- 采用 A\* 或等效算法计算格子路径。
- 路径计算需考虑移动距离限制与不可通行格。
- 玩家和敌人 AI 复用同一套寻路能力。

**DEMO验收标准：**点击合法目标格后，单位可沿有效路径移动；无法到达的目标格不可执行移动。

## 5.3 单位系统 \[P0\]

**系统目标：**建立玩家和敌人的统一棋子数据与基础状态。

**核心需求：**

- 单位至少包含：阵营、HP、AP、移动范围、当前格、武器和存活状态。
- 支持 Player、Enemy 两类基础阵营。
- 支持单位生成、占格、移动、受伤、死亡和移除。
- 同一格默认仅允许一个单位占用。

**DEMO验收标准：**场景可同时存在多个玩家单位与敌方单位，状态变化与格子占用正确同步。

## 5.4 单位选择与移动系统 \[P0\]

**系统目标：**实现玩家对己方单位的基础控制。

**核心需求：**

- 支持点击选择己方单位、取消选择和切换单位。
- 选择单位后显示当前可移动范围。
- 点击合法格后执行移动，并更新格子占用。
- 移动完成后按照规则扣除 AP。

**DEMO验收标准：**玩家可稳定完成“选择单位—查看范围—点击目标—移动到位”的完整操作。

## 5.5 回合与 AP 系统 \[P0\]

**系统目标：**建立统一回合流程与单位行动资源约束。

**核心需求：**

- 战斗阶段采用玩家阵营回合与敌方阵营回合交替。
- DEMO 默认每个单位每回合拥有 2 AP。
- 移动、攻击、交互等行为均通过 AP 消耗执行。
- 回合切换时重置本阵营单位可用 AP。
- 支持手动结束玩家回合。

**DEMO验收标准：**玩家结束回合后敌方可完成行动，并能够重新进入下一玩家回合。

## 5.6 Action 行动框架 \[P0\]

**系统目标：**以统一方式管理移动、攻击、交互等操作，避免行为逻辑直接耦合在单位对象中。

**核心需求：**

- DEMO 至少提供 Move、Attack、Interact、Loot 四类基础 Action。
- 每个 Action 具备合法性判断、AP 消耗和执行结果。
- 系统能够阻止 AP 不足或目标非法的 Action。

**DEMO验收标准：**四类基础 Action 均可通过统一流程触发、校验并完成执行。

## 5.7 基础战斗系统 \[P0\]

**系统目标：**形成可完成胜负判断的最低战棋战斗。

**核心需求：**

- 支持选择攻击目标、判断攻击距离、造成伤害并消耗 AP。
- DEMO 可先采用必中制，暂不要求复杂命中概率。
- 武器至少包含伤害、射程和 AP 消耗三个参数。
- 单位 HP 归零时死亡并释放所在格。
- 当当前战斗区域敌人全部失去战斗能力时结束交战。

**DEMO验收标准：**玩家可使用武器击败敌人，敌人也能够对玩家造成伤害并触发死亡。

## 5.8 有限视野与 LOS 系统 \[P0\]

**系统目标：**建立探索未知区域和发现敌人的基础信息规则。

**核心需求：**

- 单位拥有基础视野距离。
- 墙体等障碍物能够阻挡 LOS。
- 超出玩家当前可见范围的敌人不直接显示。
- DEMO 可采用“可见 / 不可见”两级表现，完整战争迷雾可后续增强。

**DEMO验收标准：**玩家移动后视野实时更新；被墙体遮挡或超出视野的敌人不会被直接显示。

## 5.9 探索与接敌系统 \[P0\]

**系统目标：**连接局内探索状态与正式战斗状态。

**核心需求：**

- 未交战时玩家可以移动并探索地图。
- 敌人可按照预设路线进行简单巡逻。
- 玩家进入敌人有效视野后触发交战。
- 系统能够在探索状态与战斗状态之间切换。

**DEMO验收标准：**玩家能够在未交战状态接近敌人，并通过被发现或主动攻击进入战斗。

## 5.10 敌人 AI 系统 \[P0\]

**系统目标：**提供最低可用的敌方回合行为。

**核心需求：**

- 探索状态支持固定路线巡逻。
- 战斗状态优先判断是否存在可攻击目标。
- 若目标不在攻击范围内，向最近可攻击位置移动。
- 进入有效攻击范围后执行攻击。
- DEMO 默认优先选择距离最近的玩家单位。

**DEMO验收标准：**敌方回合能够自动完成目标选择、移动与攻击，不出现明显停滞或无限循环。

## 5.11 交互物系统 \[P0\]

**系统目标：**为 Loot、撤离点等地图对象提供统一交互入口。

**核心需求：**

- 交互对象至少包含交互范围、交互条件和交互结果。
- DEMO 首批对象包含 Loot 箱与撤离点。
- 交互行为通过 Interact Action 执行并消耗对应 AP。

**DEMO验收标准：**玩家靠近有效对象后能够看到交互提示，并可成功触发对应结果。

## 5.12 Loot 与物品系统 \[P0\]

**系统目标：**形成局内搜刮收益，并为格子背包摆放、携带取舍与撤离结算提供统一物品数据。

**核心需求：**

- 物品至少包含 ID、名称、类型、价值、图标和背包占位形状。
- 每种物品通过二维格子占位数据定义其尺寸或形状，例如 1×1、1×2、2×2、L 形等。
- 物品占位形状需能够参与背包空间合法性检测，并支持旋转后的占位结果。
- DEMO 至少包含材料、消耗品、贵重品、芯片四类物品，并配置不同占位尺寸或形状以体现空间价值差异。
- Loot 箱可配置固定或随机物品列表。
- 玩家打开 Loot 容器后，可查看物品的图标、价值和占位形状，并将其拖入背包中的合法位置。
- 当背包不存在能够容纳该物品的连续合法空间时，禁止直接拾取。

**DEMO验收标准：**玩家打开 Loot 容器后能够查看并拾取不同占位形状的物品；物品只有在背包中存在合法摆放位置时才能进入背包。

## 5.13 格子背包系统 \[P0\]

**系统目标：**采用类似《逃离塔科夫》《三角洲行动》的二维格子背包，通过不同物品的占位形状与手动摆放形成空间管理和搜刷取舍。

**核心需求：**

- 背包采用固定宽 × 高的二维格子区域，例如 DEMO 可使用 6×8 或等效规模。
- 每个背包格记录当前是否被占用以及对应物品实例。
- 物品根据自身占位形状占据一个或多个连续格子，不同物品可拥有不同尺寸或不规则形状。
- 系统支持通过二维 Shape Mask 或等效数据描述物品占位，例如：
  - 1×1：小型材料、芯片。
  - 1×2 / 2×1：弹匣、医疗品。
  - 2×2：大型贵重品。
  - L 形等不规则占位：用于验证更复杂的空间拼接。
- 支持玩家在 Loot 容器与背包之间拖拽物品，并在背包内部重新调整物品位置。
- 支持物品以 90° 为单位旋转；旋转后重新计算占位形状与合法性。
- 拖拽过程中应预览物品即将占用的格子，并明确显示“可放置 / 不可放置”状态。
- 放置物品时需检测目标格是否越界、是否与其他物品重叠；任一条件不满足时禁止放置。
- 背包剩余总格数足够但无法形成对应形状的连续空间时，同样视为无法拾取，玩家需要重新整理背包。
- 支持将物品从背包丢弃至地面或 Loot 容器，作为玩家腾出空间的基础手段。
- DEMO 暂不要求自动整理、背包嵌套、保险箱、重量负重、堆叠拆分、快捷装备栏等完整功能。

**交互流程：**

1. 玩家打开 Loot 容器。
2. 选择或拖动目标物品。
3. 背包显示该物品对应的占位形状。
4. 玩家拖动或旋转物品寻找合法空间。
5. 合法位置高亮后确认放置。
6. 若无合法空间，玩家可重新整理、丢弃已有物品或放弃该战利品。

**DEMO验收标准：**

- 玩家可以拖拽、移动和旋转不同占位形状的物品。
- 物品不可越过背包边界，也不可与其他物品占位重叠。
- 系统能够正确处理“剩余格数足够，但形状无法放入”的情况。
- 玩家需要通过重新排列已有物品来腾出有效空间，并因此产生保留、丢弃或放弃 Loot 的取舍。
- 撤离结算能够正确读取背包中最终携带的物品列表。

## 5.14 撤离与结算系统 \[P0\]

**系统目标：**完成搜打撤游戏的局内闭环。

**核心需求：**

- 地图至少配置 1 个有效撤离点。
- 玩家进入撤离区域后可以主动确认撤离。
- 成功撤离后统计本局带出 Loot。
- 全队阵亡时判定行动失败，本局 Loot 不计入成功结算。
- 结果界面至少显示成功/失败与带出物品。

**DEMO验收标准：**玩家能够从进入地图完整游玩至成功撤离或失败，并得到明确结算结果。

## 5.15 基础 UI 与反馈系统 \[P0\]

**系统目标：**保证玩家能够理解当前状态并完成核心操作。

**核心需求：**

- 显示当前选中单位、HP、AP 和当前回合。
- 显示可移动格、可攻击目标和当前交互对象。
- 显示 Loot 容器与二维格子背包界面，支持物品占位预览、拖拽、旋转及合法/非法放置反馈，并显示撤离提示。
- 重要操作应提供基础文字或视觉反馈。

**DEMO验收标准：**首次接触 DEMO 的测试人员无需开发者逐步指引即可完成基础移动、攻击、搜刮和撤离。

## 5.16 Game State 游戏状态系统 \[P0\]

**系统目标：**统一管理 DEMO 各阶段的流程切换。

**核心需求：**

- 至少包含 Preparation / Exploration / Combat / Extraction / Result 状态。
- 各状态只开放对应的操作集合。
- 状态切换由明确事件触发，例如发现敌人、战斗结束或完成撤离。

**DEMO验收标准：**完整游玩过程中状态切换稳定，不出现探索、战斗和结算逻辑同时执行的冲突。

# 6. P1 特色增强系统

以下系统不影响基础闭环成立，但建议在 P0 稳定后择优加入，用于展示“战棋 × 搜打撤”的差异化体验。

| **系统** | **简要需求** | **展示价值** |
| --- | --- | --- |
| 战争迷雾 | 区分未探索、已探索、当前可见区域。 | 强化未知地图与探索感 |
| 掩体 | 单位在掩体后获得基础防御收益。 | 增加位置选择 |
| 主动伏击 | 玩家未被发现时主动攻击可获得一次有限优势。 | 强化侦察价值 |
| Push 位移 | 技能可推动单位 1 格。 | 展示位置与环境组合 |
| 爆炸物 | 可破坏对象被击毁后产生范围伤害。 | 展示连锁反应 |
| 门 | 开关门同时影响通行与 LOS。 | 展示环境交互 |
| Threat 警戒度 | 随时间或战斗逐步提高并产生增援。 | 制造撤离压力 |
| 高价值区域 | 更高风险区域配置更高价值 Loot。 | 形成“继续深入/撤离”选择 |

# 7. DEMO暂不纳入范围

- 多章节与多地图
- 完整基地建设与设施生产
- 复杂 RPG 等级与职业树
- 商人、任务线与剧情系统
- 完整护甲/穿甲/弹药经济
- 天气与昼夜循环
- 复杂 Buff / Debuff
- 基地入侵与局外时间管理
- Boss Rush 与终局内容
- 完整程序化地图生成

以上内容仅在基础 DEMO 证明核心玩法成立后进入后续版本评估。

# 8. DEMO建议内容配置

| **内容项** | **建议数量** | **说明** |
| --- | --- | --- |
| 地图 | 1 张 | 小型灰盒战区，包含分支路线 |
| 玩家单位 | 2 个 | 基础属性一致，以武器/技能体现差异 |
| 敌人类型 | 2 类 | 步枪兵、突击兵 |
| 敌人数量 | 5-7 个 | 分为 2 个主要遭遇组 |
| 武器 | 2-3 种 | 步枪、霰弹枪等 |
| Loot 类型 | 4-5 种 | 材料、消耗品、贵重品、芯片等 |
| Loot 点 | 2-3 个 | 至少 1 个高价值点 |
| 撤离点 | 1 个 | 普通撤离即可 |
| 单局时长 | 5-10 分钟 | 适合内部快速演示与测试 |

# 9. DEMO整体验收标准

1. 玩家能够从进入地图开始，独立完成至少一次“探索—接敌—战斗—搜刮—撤离—结算”流程。
2. 地图格、寻路、单位占用和移动逻辑稳定，不出现明显穿墙、叠格或无法结束行动的问题。
3. 战斗回合能够稳定循环，玩家与敌人均可完成移动和攻击。
4. 视野规则能够影响敌人发现与玩家探索，不直接暴露全部敌人信息。
5. Loot 与背包能够形成基本携带限制，撤离成功与失败具有不同结算结果。
6. DEMO 单局控制在约 5-10 分钟，可用于快速重复测试。

# 10. 建议开发顺序

1. Grid 地图格 → 阻挡 → A\* 寻路。
2. Unit 单位 → 选择 → 移动 → 格子占用。
3. Turn Manager → AP → Action 基础框架。
4. 攻击 → 伤害 → 死亡 → 基础敌人 AI。
5. LOS → 有限视野 → 探索/接敌状态切换。
6. 交互物 → Loot → 背包。
7. 撤离点 → 成功/失败 → 结算界面。
8. 补充 UI、操作反馈与 P1 特色系统。

**最终交付目标：形成一个可重复游玩的简易灰盒 DEMO，能够清晰展示“格子探索 → 回合接敌 → 战棋战斗 → 搜刮 → 主动撤离”的核心概念。**

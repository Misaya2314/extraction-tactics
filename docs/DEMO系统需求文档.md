# 1. 文档目的

本文件用于明确“关卡制战棋策略”简易 DEMO 的基础系统范围、最低功能要求与验收标准，作为程序、美术和策划拆分开发任务的统一依据。

DEMO 不追求完整内容量与长期可玩性，优先验证核心玩法是否可以形成完整、可理解、可操作的体验闭环。

# 2. DEMO体验目标

- 玩家能够在格子化地图中控制多个单位进行移动、攻击与交互。
- 玩家能够通过有限视野探索地图，并在发现敌人后进入回合制战斗。
- 玩家能够通过站位、AP 分配、武器和技能配合完成关卡目标。
- 玩家能够在开局理解胜利条件与失败条件。
- 目标完成或全队阵亡后获得明确结果，并可重试关卡。

# 5. P0 基础系统需求

## 5.1 Grid 地图格系统 \[P0\]

**系统目标：**建立战棋地图的统一空间表达，为移动、寻路、占用、视野和交互提供基础数据。

**核心需求：**

- 采用方形格作为 DEMO 默认地图单元。
- 每个格子记录格子坐标、世界坐标、是否可通行、占用状态和基础高度信息。
- 支持世界坐标与格子坐标双向转换。
- 支持查询相邻格、合法移动格和格子占用对象。
- 支持可移动格、目标格等基础可视化高亮。

**DEMO验收标准：**玩家可在灰盒场景中看到有效格子范围；系统能够正确判断可走与不可走区域。

## 5.2 地图阻挡与寻路系统 \[P0\]

**系统目标：**保证单位能够按照规则在格子地图中计算并执行有效移动路径。

**核心需求：**

- 墙体、关闭的门、占用格等对象可阻止通行。
- 采用 A\* 或等效算法计算格子路径。
- 路径计算需考虑移动距离限制与不可通行格。
- 玩家和敌人 AI 复用同一套寻路能力。

**DEMO验收标准：**点击合法目标格后，单位可沿有效路径移动；无法到达的目标格不可执行移动。

## 5.3 单位系统 \[P0\]

**系统目标：**建立玩家和敌人的统一棋子数据与基础状态。

**核心需求：**

- 单位至少包含：阵营、HP、AP、移动范围、当前格、武器和存活状态。
- 支持 Player、Enemy 两类基础阵营。
- 支持单位生成、占格、移动、受伤、死亡和移除。
- 同一格默认仅允许一个单位占用。

**DEMO验收标准：**场景可同时存在多个玩家单位与敌方单位，状态变化与格子占用正确同步。

## 5.4 单位选择与移动系统 \[P0\]

**系统目标：**实现玩家对己方单位的基础控制。

**核心需求：**

- 支持点击选择己方单位、取消选择和切换单位。
- 选择单位后显示当前可移动范围。
- 点击合法格后执行移动，并更新格子占用。
- 移动完成后按照规则扣除 AP。

**DEMO验收标准：**玩家可稳定完成“选择单位—查看范围—点击目标—移动到位”的完整操作。

## 5.5 回合与 AP 系统 \[P0\]

**系统目标：**建立统一回合流程与单位行动资源约束。

**核心需求：**

- 战斗阶段采用玩家阵营回合与敌方阵营回合交替。
- DEMO 默认每个单位每回合拥有 2 AP。
- 移动、攻击、交互等行为均通过 AP 消耗执行。
- 回合切换时重置本阵营单位可用 AP。
- 支持手动结束玩家回合。

**DEMO验收标准：**玩家结束回合后敌方可完成行动，并能够重新进入下一玩家回合。

## 5.6 Action 行动框架 \[P0\]

**系统目标：**以统一方式管理移动、攻击、交互等操作，避免行为逻辑直接耦合在单位对象中。

**核心需求：**

- DEMO 至少提供 Move、Attack、Interact 三类基础 Action。
- 每个 Action 具备合法性判断、AP 消耗和执行结果。
- 系统能够阻止 AP 不足或目标非法的 Action。

**DEMO验收标准：**三类基础 Action 均可通过统一流程触发、校验并完成执行。

## 5.7 基础战斗系统 \[P0\]

**系统目标：**形成可完成胜负判断的最低战棋战斗。

**核心需求：**

- 支持选择攻击目标、判断攻击距离、造成伤害并消耗 AP。
- DEMO 可先采用必中制，暂不要求复杂命中概率。
- 武器至少包含伤害、射程和 AP 消耗三个参数。
- 单位 HP 归零时死亡并释放所在格。
- 当前遭遇敌人全部失去战斗能力时可结束交战；是否关卡胜利由关卡目标统一判断。

**DEMO验收标准：**玩家可使用武器击败敌人，敌人也能够对玩家造成伤害并触发死亡。

## 5.8 有限视野与 LOS 系统 \[P0\]

**系统目标：**建立探索未知区域和发现敌人的基础信息规则。

**核心需求：**

- 单位拥有基础视野距离。
- 墙体等障碍物能够阻挡 LOS。
- 超出玩家当前可见范围的敌人不直接显示。
- DEMO 可采用“可见 / 不可见”两级表现，完整战争迷雾可后续增强。

**DEMO验收标准：**玩家移动后视野实时更新；被墙体遮挡或超出视野的敌人不会被直接显示。

## 5.9 探索与接敌系统 \[P0\]

**系统目标：**连接局内探索状态与正式战斗状态。

**核心需求：**

- 未交战时玩家可以移动并探索地图。
- 敌人可按照预设路线进行简单巡逻。
- 玩家进入敌人有效视野后触发交战。
- 系统能够在探索状态与战斗状态之间切换。

**DEMO验收标准：**玩家能够在未交战状态接近敌人，并通过被发现或主动攻击进入战斗。

## 5.10 敌人 AI 系统 \[P0\]

**系统目标：**提供最低可用的敌方回合行为。

**核心需求：**

- 探索状态支持固定路线巡逻。
- 战斗状态优先判断是否存在可攻击目标。
- 若目标不在攻击范围内，向最近可攻击位置移动。
- 进入有效攻击范围后执行攻击。
- DEMO 默认优先选择距离最近的玩家单位。

**DEMO验收标准：**敌方回合能够自动完成目标选择、移动与攻击，不出现明显停滞或无限循环。

## 5.11 交互物系统 \[P0\]

**系统目标：**为门、开关等战术对象提供统一交互入口。

**核心需求：**

- 交互对象至少包含交互范围、交互条件和交互结果。
- DEMO 至少使用一个可交互对象验证入口，例如开关；对象状态若影响通行、LOS 或掩体，必须同步更新对应规则。
- 交互行为通过 Interact Action 执行并消耗对应 AP。

**DEMO验收标准：**玩家靠近有效对象后能够看到交互提示，并可成功触发对应结果。

## 5.12 关卡目标系统 [P0]

**系统目标：**由关卡配置提供明确的胜利与失败条件。

- Demo 使用歼灭目标：关卡规定的全部目标敌人失去战斗能力后胜利；全队失去战斗能力后失败。
- 目标敌人集合由关卡定义，不能用当前可见敌人或单个遭遇组替代。
- 完成一次行动的全部规则效果后检查胜负，含连锁爆炸等后续效果；同次结算满足双方条件时失败优先。
- 目标进度可被读取、显示和恢复，关卡目标与 UI 使用同一规则来源。
- 占领、守卫、护送等目标为后续扩展，不要求本阶段实现。

**DEMO验收标准：**最后一个目标敌人死亡触发胜利，全队阵亡触发失败；仅清空可见敌人或结束局部交战不会提前判胜。

## 5.13 关卡初始化与重试 [P0]

- 根据关卡配置创建玩家、敌人、环境与目标初始状态。
- 提供重试和返回关卡入口操作，Demo 入口可为简报界面，不要求多关选择系统。
- 重试清空上一局的损伤、目标进度、回合状态、撤销记录和临时对象，避免旧异步回调影响新战局。
- 不依赖库存、基地或上一局带出物资；失败不产生永久装备损失。

**DEMO验收标准：**胜利和失败后均可重新开始相同关卡，所有规则状态与初始配置一致。

## 5.14 胜负与结果结算 [P0]

- 由目标系统提交唯一终局结果，进入结果状态后停止玩法输入和回合推进。
- 结果界面至少显示胜负、结束原因和目标完成情况，可附带回合数及己方存活数。
- 不要求撤离点、撤离确认、带出物品或价值统计。

**DEMO验收标准：**结果准确且只提交一次，后续动画或信号不会覆盖结果或再次推进回合。

## 5.15 基础 UI 与反馈 [P0]

- 简报显示关卡目标、失败条件和预设小队。
- HUD 显示当前单位、HP、AP、回合、目标进度。
- 显示移动范围、可攻击目标和交互对象；非法操作提供可理解的原因。
- 提供结束回合、结果查看、重试和返回入口操作。
- Loot 容器与格子背包不作为必需界面。

**DEMO验收标准：**首次接触 Demo 的测试者能够独立完成移动、攻击、结束回合并理解胜负原因。

## 5.16 Game State 游戏状态系统 [P0]

- 目标流程包含 Preparation / Exploration / Combat / Result；保留侦察与接敌，不要求废除现有探索阶段。
- 开局简报后进入关卡，发现敌人或主动攻击触发交战，局部交战结束且关卡未结束时可以返回探索。
- 关卡目标系统从活动战局提交胜负后进入 Result，各状态仅开放合法操作。
- 旧 Extraction 状态属于兼容实现，不作为新关卡必经阶段；实际代码需后续迁移，本文不宣称已经完成。

**DEMO验收标准：**完整关卡不依赖 Extraction 即可结束；胜负结算、重试与阶段切换不会相互冲突。

# 6. P1 战术增强系统

| 系统 | 需求 | 展示价值 |
| --- | --- | --- |
| 掩体与侧翼 | 使用统一规则计算保护及绕侧效果 | 位置选择 |
| 主动伏击 | 明确先手优势的条件和边界 | 侦察价值 |
| 技能与位移 | 用已有技能或强制位移形成组合 | 小队协同 |
| 环境爆炸 | 破坏对象后结算范围与连锁效果 | 环境利用 |
| 战争迷雾 | 区分未知、已探索和当前可见区域 | 信息判断 |
| 关卡事件 | 可预告的增援或环境变化 | 目标推进中的战术变化 |
| 撤销 | 恢复规则和目标进度，明确不可撤销边界 | 战术试错 |

已有 P1 实现可继续使用；涉及 P0 胜负、恢复或重试时必须同步更新，不能因列为 P1 而保留状态冲突。

# 7. 当前不纳入范围

- 搜刮收益、随机贵重品、背包空间经营与物资带出。
- 强制撤离点及风险撤离循环。
- 基地、生产、交易、局外资源成长与失败永久损失。
- 完整芯片系统、复杂 RPG 职业树、护甲与弹药经济。
- 天气、昼夜、完整程序化地图及大规模多关内容。

已有 Loot、格子背包、旧撤离对象和相关资源可保留兼容，不构成新需求，也不要求本次文档修改删除实现。

# 9. Demo 整体验收标准

1. 玩家独立完成“简报—侦察接敌—战斗—目标判定—结果—重试”。
2. 移动、寻路、占用、AP 与敌方回合稳定，无穿墙、叠格或无法结束行动。
3. 视野影响情报，掩体、技能等启用规则的预览与执行一致。
4. 目标进度与胜负正确，局部战斗结束不会误判全关胜利。
5. 无需搜刮、背包或撤离点即可完成关卡并查看结果。
6. 重试恢复初始状态；启用撤销时同步恢复目标，结算后禁止撤销。

地图系统自动测试使用合成 fixture，不绑定具体地图布局；实际关卡内容按编辑器校验与人工试玩验收。系统级测试应覆盖目标完成、全队阵亡、同时满足胜负、终局重复信号及重试状态恢复。

# 10. 现有实现迁移顺序

1. 复用 Grid、Unit、Turn、AP、Action、战斗与感知基础。
2. 增加关卡目标配置、运行时进度和统一胜负判定。
3. 调整 Game State，使战局直接进入 Result，脱离强制 Extraction 流程。
4. 调整简报、HUD、结算及重试；同步快照与撤销的目标状态。
5. 将地图撤离点必填与可达性要求迁为按目标类型校验。
6. 用一张无强制 Loot 和撤离点的关卡验证新闭环，再完善 P1 战术反馈。

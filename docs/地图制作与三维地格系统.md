# 地图制作与三维地格系统

## 1. 坐标约定

所有玩法地格统一使用 `Vector3i(x, level, z)`：

- `x`：地图东西方向。
- `level`：逻辑楼层，写在 `Vector3i.y` 中。
- `z`：地图南北方向。
- 默认地格尺寸为 `(2, 2, 2)` 米，因此 `Vector3i(4, 1, 3)` 的世界坐标是 `(8, 2, 6)`。

地图不是六方向体素。单位只能在同层的四个水平相邻格之间移动。楼梯、坡道、梯子和单向跳落必须放置 `TraversalLink3D`；同一 X/Z 上下叠放两块地板不会自动连通。

## 2. 编辑器地图结构

打开 `res://scenes/map_authoring/prototype_map_authoring.tscn`，场景结构如下：

```text
PrototypeMapAuthoring (TacticalMapAuthor)
├── FloorGrid             # 可站立表面；它决定哪些 Vector3i 地格存在
├── StructureGrid         # 墙体和掩体；可与 FloorGrid 同格叠放
├── DecorationGrid        # 边界和纯表现，不进入玩法数据
├── Objects               # Loot、油桶、门、撤离点等 MapObjectMarker3D
├── Spawns                # 玩家和敌人的 UnitSpawnMarker3D
├── PatrolRoutes          # PatrolRoute3D
├── TraversalLinks        # 楼梯/坡道/梯子/跳落
└── TraversalVisuals      # 连接的灰盒模型；只负责表现和点击碰撞
```

`FloorGrid` 和 `StructureGrid` 使用 `res://assets/prototype/grid/prototype_mesh_library.tres`。当前素材包括普通地板、交替色地板、墙和低掩体。

## 3. 新建或修改地图

### 绘制地面

1. 复制 `prototype_map_authoring.tscn` 作为新地图。
2. 选择根节点 `TacticalMapAuthor`，设置：
   - `map_id`
   - `footprint_size`，其中 Y 表示 Z 方向长度
   - `level_count`
   - `cell_dimensions`
   - `output_resource_path`
3. 选择 `FloorGrid`，在 Godot 3D GridMap 面板选择 Floor 或 FloorAlt。
4. 在 GridMap 的第 0 层绘制底层地面；切换到第 1、2 层绘制平台或楼层。

只有 `FloorGrid` 中实际存在的单元格才会成为可站立地格，因此支持不规则地图、空洞和同 X/Z 多层表面。

### 绘制墙与掩体

选择 `StructureGrid`，在已经有地板的相同坐标绘制 Wall 或 LowCover。旋转 GridMap 项目时，烘焙器会同步旋转掩体的 N/E/S/W 方向掩码。

地块规则位于 `res://assets/prototype/grid/prototype_tile_catalog.tres`，不要通过节点名称表达规则。每种 GridMap 项目都要配置：

- 是否可通行
- 移动消耗
- 是否阻挡 LOS
- 遮挡物高度
- 四方向掩体边

### 添加跨层连接

在 `TraversalLinks` 下创建 `TraversalLink3D`：

- `from_cell` / `to_cell`：完整三维坐标。
- `move_cost`：跨越连接所需移动点。
- `bidirectional`：关闭后可制作单向跳落。
- `kind`：Stairs、Ramp、Ladder、Drop 或 Custom。

连接只定义规则。楼梯或坡道模型放在 `TraversalVisuals`，并应具备地面碰撞，以便鼠标射线能够选择高层表面。

### 添加玩法对象

- 单位出生：创建 `UnitSpawnMarker3D`，配置阵营、地格、朝向和可选巡逻路线 ID。
- Loot/撤离点/油桶/门：创建 `MapObjectMarker3D`，配置对象 ID、类型、地格、场景和阻挡属性。
- 巡逻路线：创建 `PatrolRoute3D`，按顺序填写 `Array[Vector3i]`。

Marker 的 `cell` 是权威数据。选择根节点并点击 `Snap Markers`，可以将全部 Marker 重新吸附到地格中心。

## 4. 校验与烘焙

选择 `TacticalMapAuthor` 根节点：

- `Validate Map`：只检查，不写文件。
- `Bake Map`：校验成功后，将地图写入 `output_resource_path` 指定的 `.tres`。

当前校验包含：

- GridMap 尺寸和 Transform 是否统一。
- GridMap item 是否都有 TileCatalog 规则。
- 墙、掩体和 Marker 下方是否存在地板。
- 出生点是否有效、是否重复占格。
- 是否至少有一个玩家出生点和撤离点。
- 跨层连接两端是否存在。
- 巡逻点是否存在且互相可达。
- 每个玩家出生点是否能抵达撤离点。

运行时只读取烘焙后的 `TacticalMapDefinition`，不要手工编辑生成的 `.tres`。

## 5. 接入游戏场景

在使用 `PrototypeController` 的主场景中：

1. 把作者地图场景实例化为 Environment。
2. 将烘焙出的 `.tres` 拖到控制器的 `map_definition` 属性。
3. 运行场景。

控制器会从资源创建 `GridModel`、遮挡数据、出生单位和巡逻路线。单位位置、高亮与移动路径均通过 `cell_to_world(Vector3i)` 获得正确高度；鼠标选择通过物理射线命中地面，不再固定投影到 Y=0。

## 6. 当前高度规则

- 路径是加权 Dijkstra：目标地形和跨层连接的 `move_cost` 都参与路线选择。
- 攻击和视野距离为 `|dx| + |dz| + |dlevel|`。
- LOS 使用 X/Z supercover，并按射线进度插值逻辑楼层；不同楼层的遮挡键不会互相覆盖。
- 更精确的“眼睛高度—遮挡物高度—高地越过低掩体”属于下一阶段；当前已经保存 `occluder_height`，但尚未进入连续高度射线计算。

# 1. 文档目的与架构概述

本文件定义项目技能系统的正式开发架构、数据合同、插槽装配规则、行动管线裁决、快照撤销机制与交互实现规范。

本系统严格遵循项目《通用开发规则文档》与《定义与运行时实例分离开发文档》的核心规范：
- **静态定义与运行时状态彻底解耦**：技能的基础参数（名称、消耗、射程、冷却配置、生效策略）作为只读资源存在；技能当前的剩余 CD 与可用次数由轻量运行时个体（`SkillInstance`）持有。
- **插槽可插拔化（Pluggable Slots）**：单位本体不硬编码任何具体技能，通过标准化插槽（默认 2 个）装配技能实例，支持运行时换装与卸下。
- **统一接入 Action 权威管线**：技能释放被定义为一等公民行动（`ACTION_SKILL`），经由 `ActionValidator` 进行前置安全校验、`ActionExecutor` 扣除 AP 并调度执行，严禁表现层擅自扣费或修改战斗数据。
- **撤销/重做（Undo/Redo）透明支持**：技能的状态（冷却轮数、充能）完整纳入 `UnitStateSnapshot`，玩家撤销单步移动或战术动作时，技能状态同步无损还原。
- **纯鼠标操作人机交互**：ActionBar 动态感知选中单位的槽位技能，支持单键点击自施放或地格点选瞄准，免除键盘快捷键束缚。

### 技能执行总链路

```text
SkillDefinition (.tres 只读静态模板与策略)
        ↓ 实例化 (UnitInstanceFactory)
SkillInstance (持有 stable instance_id, current_cooldown, current_charges)
        ↓ 装配到插槽 (equip_skill)
UnitRuntimeState (MAX_SKILL_SLOTS = 2，槽位变更与 CD 递减信号)
        ↓ 玩家点击 UI 或 AI 决策
ActionRequest (action_type: ACTION_SKILL, slot_index, target_cell)
        ↓ 权威校验 (ActionValidator)
ActionValidator.validate_skill() (AP/CD/射程/LOS/存活检验)
        ↓ 权威执行 (ActionExecutor)
ActionExecutor (扣减 AP -> 执行技能效果 -> 触发技能冷却 -> 发射状态信号)
        ↓ 记录与反馈
PrototypeController (UI 更新 / 战场破坏 / 记录单步 Undo 快照)
```

# 2. 核心设计原则与系统边界

## 2.1 核心设计原则

1. **静态定义只读共享 (Immutable Definition)**：
   `SkillDefinition` 继承自 `Resource`，为所有同类技能共享的只读模板。严禁在 `SkillDefinition` 中保存诸如 `current_cooldown` 等局内状态。
2. **运行时个体独立 (Runtime Instance Identity)**：
   `SkillInstance` 继承自 `RuntimeInstance`，拥有稳定唯一的 `instance_id`。同一单位装配的两个技能或两个单位装配的同名技能，拥有彼此独立的 CD 计数与可用次数。
3. **槽位解耦与弹性装配 (Slot Decoupling)**：
   单位定义 `UnitArchetype` 通过 `default_skills: Array[SkillDefinition]` 声明默认技能，工厂在初始化时自动装配；单位运行时状态 `UnitRuntimeState` 支持 `equip_skill(slot_index, skill)` 与 `unequip_skill(slot_index)` 动态热插拔。
4. **统一单一来源 (Single Source of Truth)**：
   伤害扣除、地格破坏、AP 消耗全部经由 Action 系统权威结算。UI 和控制器仅作为 View 和 Input 处理者，不直接判定命中与伤害。
5. **单步撤销对称性 (Deterministic Undo)**：
   单步撤销（Undo）必须恢复该步骤前单位的所有属性，包括技能插槽内的冷却状态，防止出现利用撤销刷技能 CD 的漏洞。

## 2.2 本阶段范围与非目标

### 本阶段包含范围
- 基础抽象：`SkillDefinition` 与 `SkillInstance`。
- 单位槽位管理：2 槽位配置、插槽换装、回合初 CD 递减通知。
- 行动管线扩展：新增 `ACTION_SKILL` 类型常量、技能校验逻辑与执行注册。
- 快照与恢复：`UnitStateSnapshot` 序列化与还原技能插槽状态。
- 首发范例技能：
  - `GrenadeSkillDefinition`（破片手雷：地格投掷、3x3 范围 AoE、破坏障碍物与掩体）。
  - `SprintSkillDefinition`（战术冲刺：自身施放、+3 格本回合临时机动点数）。
- 表现层与交互：ActionBar 动态技能按钮绑定、纯鼠标选地施法、高亮投掷范围、撤销联动。

### 本阶段非目标
- 复杂的技能树与天赋加点系统。
- 引导型持续施法（Channeled Skills）与技能打断。
- 跨多回合生效的持续性地面危险区域（如持续燃烧火焰地格，后续结合环境系统实现）。
- 技能被动光环（Aura）机制。

# 3. 核心类设计与数据合同

```

├── skill_definition.gd          # 技能静态定义基类（数据配置 + 虚策略接口）

└── sprint_skill_definition.gd   # 战术冲刺策略实现
```

## 3.1 静态定义：`SkillDefinition`

`SkillDefinition` 继承自 `Resource`，使用 `@tool` 支持编辑器配置与资源预览。

### 核心属性合同

| 属性名 | 类型 | 默认值 | 描述 |
| --- | --- | --- | --- |
| `skill_id` | `StringName` | `&""` | 技能唯一静态标识符（如 `&"tactical_grenade"`） |
| `display_name` | `String` | `""` | 技能本地化展示名称 |
| `description` | `String` | `""` | 技能功能多行描述 |
| `icon` | `Texture2D` | `null` | 技能 UI 图标资源 |
| `ap_cost` | `int` | `1` | 释放所需的行动点数（AP） |
| `cooldown_turns`| `int` | `2` | 基础冷却回合数（施放后进入该 CD，下回合初开始递减） |
| `max_charges` | `int` | `0` | 最大充能次数（0 表示无充能限制，仅受 CD 约束） |
| `target_type` | `TargetType` | `TARGET_CELL` | 目标类型：`SELF(0)`, `TARGET_CELL(1)`, `TARGET_UNIT(2)` |
| `cast_range` | `int` | `4` | 最大施法曼哈顿距离（针对目标格或单位） |
| `aoe_radius` | `int` | `0` | AoE 辐射半径（0 表示单格，1 表示以目标为中心的 3x3 区域） |
| `require_los` | `bool` | `true` | 是否必须具备直射视线（抛射类技能如手雷可设为 false） |

### 关键虚方法接口

```gdscript
## 校验技能资源配置是否完整合法
func is_valid() -> bool

## 虚方法：计算可高亮选取的合法目标格列表
func get_valid_target_cells(actor_cell: Vector3i, grid: Variant) -> Array[Vector3i]

## 虚策略方法：执行技能的核心效果（子类重写）
func execute_skill(request: Variant, context: Variant) -> ActionResult
```

## 3.2 运行时个体：`SkillInstance`

`SkillInstance` 继承自 `RuntimeInstance`，管理技能在局内的具体状态。

### 核心属性合同

| 属性名 | 类型 | 描述 |
| --- | --- | --- |
| `instance_id` | `StringName` | 稳定唯一的运行时实例 ID（如 `&"skill_inst_1"`） |
| `definition_type` | `StringName` | 固定为 `&"skill"` |
| `definition_id` | `StringName` | 对应的 `skill_id` |
| `definition` | `SkillDefinition`| 关联的只读定义资源引用 |
| `current_cooldown`| `int` | 当前剩余冷却回合数（0 表示冷却就绪） |
| `current_charges` | `int` | 当前剩余可用充能次数 |

### 核心接口

- `is_ready() -> bool`：判断技能是否可用（`current_cooldown <= 0` 且当充能有限时 `current_charges > 0`）。
- `trigger_cooldown() -> void`：触发冷却，令 `current_cooldown = definition.cooldown_turns`，并扣减一次充能。
- `on_turn_started() -> void`：回合开始时递减 1 点冷却时间（最小为 0）。
- `to_snapshot_dict() -> Dictionary`：导出用于保存与撤销的字典快照。
- `from_snapshot_dict(data: Dictionary, resolved_def: SkillDefinition) -> SkillInstance`：从快照重建实例。

## 3.3 单位插槽管理：`UnitRuntimeState`

单位运行时状态内置两槽位技能管理器：

```gdscript
const MAX_SKILL_SLOTS: int = 2
var _skill_slots: Array = [null, null]

signal skill_slot_changed(slot_index: int, previous: Variant, current: Variant)
signal skill_cooldown_changed(slot_index: int, cooldown: int)
```

### 插槽 API

| 方法签名 | 返回值 | 说明 |
| --- | --- | --- |
| `get_skill(slot_index: int)` | `SkillInstance` | 获取指定槽位的技能实例，越界返回 null |
| `get_equipped_skills()` | `Array[SkillInstance]` | 获取当前装备的所有有效技能列表 |
| `equip_skill(slot_index: int, new_skill: Variant)` | `bool` | 将技能装配到指定槽位，发出 `skill_slot_changed` 信号 |
| `unequip_skill(slot_index: int)` | `SkillInstance` | 卸下指定槽位的技能并清空插槽 |
| `on_turn_started()` | `void` | 回合开始时遍历插槽递减 CD，并发射 `skill_cooldown_changed` |

## 3.4 模板装配与生成：`UnitArchetype` & `UnitInstanceFactory`

在单位静态配置 `UnitArchetype` 中支持声明默认技能集合：
```gdscript
@export var default_skills: Array[SkillDefinition] = []
```

`UnitInstanceFactory` 在生成单位实例时，遍历 `default_skills`，通过 `IdService` 分配唯一的 `instance_id` 并装配至单位插槽：

```gdscript
# UnitInstanceFactory 中的装配片段
for i in range(mini(archetype.default_skills.size(), UnitRuntimeState.MAX_SKILL_SLOTS)):
    var skill_def = archetype.default_skills[i]
    if skill_def != null and skill_def.is_valid():
        var skill_inst = create_skill_instance(skill_def, id_service)
        unit_state.equip_skill(i, skill_inst)
```

# 4. 行动管线接入 (Action Pipeline Integration)

技能执行完全纳入核心行动管线，确保规则校验的权威性。

## 4.1 行动类型与参数

- **行动类型**：`ACTION_SKILL = &"skill"`
- **Payload 载荷结构**：
  ```gdscript
  {
      &"slot_index": int,           # 施放的技能插槽索引（0 或 1）
      &"target_cell": Vector3i,     # 技能选取的逻辑目标地格
      &"target_unit_id": StringName # 目标单位 ID（针对 TARGET_UNIT 技能）
  }
  ```

## 4.2 校验契约：`ActionValidator.validate_skill`

在施放前进行纯函数校验，确保施放条件严格成立：

| 校验阶段 | 拒决 Reason | 失败条件 |
| --- | --- | --- |
| AP 消耗检查 | `REASON_INVALID_COST` / `REASON_NO_AP` | 技能配置 AP 非法或角色当前 AP 小于消耗 |
| 目标有效性 | `REASON_INVALID_TARGET` | 目标格无效 |
| 装配检查 | `&"skill_not_equipped"` | 对应插槽为空或技能不存在 |
| 冷却检查 | `&"skill_not_ready"` | 技能当前仍在冷却或无可用次数 |
| 距离检查 | `REASON_OUT_OF_RANGE` | 目标格距施法者曼哈顿距离超出 `cast_range` |
| 视线检查 | `&"no_los"` | 技能需要视线（`require_los == true`）且 LOS 被墙体遮挡 |
| 存活检查 | `&"target_dead"` | 目标单位已死亡（针对单位指向技能） |

通过所有校验后，返回 `ActionResult.accepted(actor_id, &"", ap_cost, ACTION_SKILL)`。

## 4.3 执行契约：`ActionExecutor`

1. 调度预注册的技能处理器（`_handle_skill_action`）。
2. 调用具体技能定义的 `execute_skill(request, context)` 产生实际游戏效果。
3. 执行成功后：
   - 权威扣除施法者的 Action Points。
   - 调用 `skill_instance.trigger_cooldown()` 触发冷却。
   - 发射 `skill_cooldown_changed` 信号驱动 UI 更新。
   - 返回包含 `affected_units`、`destroyed_objects`、`damage` 等元数据的 `ActionResult`。

# 5. 快照与单步撤销 (Undo/Redo)

为了保证战术回合制游戏的悔棋体验，技能状态无缝接入 `UnitStateSnapshot`。

### 数据流转：
1. **生成快照**（`UnitRuntimeState.create_snapshot()`）：
   遍历 `_skill_slots`，将每个非空技能实例序列化为轻量字典：
   ```gdscript
   {
       &"instance_id": "skill_inst_1",
       &"definition_id": "tactical_grenade",
       &"current_cooldown": 2,
       &"current_charges": 0,
       &"state_version": 1
   }
   ```
   保存至 `snapshot.skill_slots_data`。
2. **恢复快照**（`UnitRuntimeState.restore_from_snapshot(snapshot)`）：
   读取 `snapshot.skill_slots_data`，按插槽索引对齐，原子还原 `current_cooldown` 与 `current_charges`，并同步触发 `skill_cooldown_changed` 刷新界面状态。

# 6. UI 与人机交互规范 (纯鼠标驱动)

本系统全面采用无键盘依赖的纯鼠标操作交互。

```
+-----------------------------------------------------------------------------------+
|  HUD / ActionBar                                                                  |
|  +--------------+  +--------------+  +--------------------+  +-----------------+  |
|  | [移动] (AP1) |  | [射击] (AP1) |  | [破片手雷] (AP1)   |  | [战术冲刺] (AP1)|  |
|  +--------------+  +--------------+  +--------------------+  +-----------------+  |
+-----------------------------------------------------------------------------------+
```

### 交互逻辑：
1. **按钮状态绑定**：
   - 当选中单位时，`PrototypeController` 检索该单位 0/1 号槽位的技能。
   - 若槽位为空，按钮显示未装备并禁用；
   - 若技能处于 CD，按钮文字追加 `[冷却 (X)]` 并禁用；
   - 若 AP 不足，按钮置灰禁用；
   - 可用状态下，高亮提示 AP 消耗与技能名。
2. **自身施放类（`TargetType.SELF`）**：
   - 点击技能按钮，立即向 `ActionExecutor` 发起请求并直接施放，无需二次确认。
3. **地格瞄准类（`TargetType.TARGET_CELL`）**：
   - **进入瞄准态**：点击技能按钮，控制器切换至 `ACTION_MODE_SKILL`，地格高亮显示橙色施法范围网格（`SKILL_HIGHLIGHT_COLOR`）。
   - **悬停预览**：鼠标悬停在合法网格上方时，依据 `aoe_radius` 动态高亮 3x3 作用区域。
   - **确认施法**：左键单击合法目标格，提交执行；执行完成后自动退出瞄准态，恢复默认选择。
   - **取消瞄准**：左键单击有效范围外的任意地格切换为未选中状态，或再次点击该技能按钮取消，不扣除任何 AP。
4. **技能描述悬停提示 (Tooltip)**：
   - 鼠标悬停在技能按钮上方时，自动弹出多行标准 Tooltip，展示技能名称、消耗 AP、冷却时间、射程与作用范围、详细效果描述以及当前剩余 CD 状态。

# 8. 扩展开发指南：如何添加一个新技能

若需要为游戏增加新技能（例如“医疗包急救”），遵循以下标准开发流程：

1. **编写策略类**：
   在 `scripts/core/skills/` 下新建脚本（如 `heal_skill_definition.gd`），继承 `SkillDefinition`。
   重写 `_init()` 配置基础数值（`skill_id = &"tactical_heal"`, `ap_cost = 2`, `cooldown_turns = 3`, `target_type = TargetType.TARGET_UNIT`）。
   重写 `execute_skill(request, context)` 实现生命回复逻辑。
2. **创建资源实例**：
   在 `resources/skills/` 目录下创建 `tactical_heal.tres`，加载该脚本并配置数值与图标。
3. **注册内容清单**：
   打开 `resources/content/game_content_manifest.tres`，在 `skills` 数组中添加该 `.tres`。
4. **装配到单位模板**：
   在 `resources/units/` 的单位原型资源（如 `player_alpha.tres`）中的 `default_skills` 数组中加入该技能资源。
5. **编写针对性单元测试**：
   在 `tests/skills/` 中追加装配、释放、冷却和撤销的断言验证。

# 9. 质量保证与测试规范

技能系统配备完善的自动化测试套件（`tests/skills/skill_system_test.gd`），覆盖全链路生命周期：

- **基础定义与验证测试**：验证非法参数拒决、默认值完整性。

# 关卡目标与行动结算

更新日期：2026-09-07。本文件记录已接入的首版关卡流程；目标类型目前只支持歼灭。

## 关卡配置

在 `TacticalMapAuthor` 根节点配置 `objective_spawn_ids`，然后 Bake。该字段会写入 `TacticalMapDefinition`：

- 留空：以地图中全部敌人出生点为目标。
- 非空：填写目标敌人的 `spawn_id`，不使用单位显示名、当前遭遇组或可见敌人列表。
- 不存在、非敌人或重复目标 ID 会在烘焙时报告错误。
- 地图不再要求撤离点，也不检查出生点到旧撤离点的可达性。
- 纯地形地图仍可烘焙；实际开始战局时必须存在有效目标敌人，且单位生成成功，否则控制器拒绝开始。

旧地图无需补填目标字段即可使用“消灭全部敌人”。旧 Loot 与撤离资源保留兼容；正式关卡不会通过撤离提交胜利。

## 目标与胜负

`MissionObjective` 保存本次关卡的目标实例 ID 集合。完成数量从目标单位的权威存活状态计算，不另存一份击杀计数。死亡单位继续保留实例，以支持现有撤销恢复。

清空局部遭遇后可以返回探索；只有全部目标完成才调用 `GameStateManager.complete_mission()`。全队阵亡优先于目标完成，因此同次结算双方全灭判失败。结果只能提交一次，结算后禁止行动、回合推进和撤销。

HUD 显示目标进度和战斗回合。结果界面显示胜负、原因、完成数量及己方存活数，不再显示物资带出价值。开局提示明确歼灭目标与全队阵亡条件。

## 行动结算边界

现有 ActionExecutor 保持“校验 → 执行效果 → 提交 AP”的约定。控制器围绕这段同步规则执行开启效果批次：

1. 单位死亡立即更新存活状态、占格和回合名单。
2. 暂缓遭遇胜负与会话胜负，继续处理技能范围伤害和环境连锁效果。
3. ActionExecutor 返回后，先检查全队阵亡，再检查目标完成。
4. 若关卡未结束，再处理局部遭遇结束、解除警报等流程。
5. 表现收尾不得重新开放终局输入或进入下一回合。

技能或爆炸导致施法者死亡时，行动仍算执行成功，不会在效果全部生效后被错误报告为 AP 提交失败。未来若引入异步规则效果，必须显式延长同一结算批次；当前批次覆盖同步效果，动画不决定规则结果。

## 撤销与重试

目标进度由恢复后的单位状态自动重建；战斗回合数加入现有撤销快照。胜利或失败后通过重载当前场景重试，重新创建目标、单位、环境和回合状态，不继承战损或物品损失。
